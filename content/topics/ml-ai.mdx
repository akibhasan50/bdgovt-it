## Learning types

Machine learning = branch of AI where computers learn from data, find patterns and decide **without being explicitly programmed**; performance improves with experience.

| Paradigm | Data | Mechanism | Applications |
| --- | --- | --- | --- |
| Supervised | **labelled** | map inputs to known outputs | spam filter, price prediction, image classification |
| Unsupervised | **unlabelled** | discover hidden patterns/groups | customer segmentation, clustering, anomaly detection |
| Reinforcement | generated by interaction | trial-and-error with rewards | robotics, game playing, autonomous systems |

- **Supervised subtasks:** classification (discrete), regression (continuous).
- **Unsupervised extras:** K-means, DBSCAN, PCA.
- **RL vocabulary:** agent, environment, reward, policy (Q-learning, policy gradient).

<Callout type="tip">
"Which uses labelled data?" → supervised. "Which groups without labels?" → unsupervised. These two fill a whole slide of any AI module MCQ set — and the three-paradigm comparison recurs every year [Combined Bank SO(IT) 2024, AP-2022].
</Callout>

## Algorithms worth knowing by category

| Category | Algorithms |
| --- | --- |
| Classification | Decision tree, Naive Bayes, KNN, SVM, logistic regression |
| Regression | Linear, polynomial, ridge/lasso |
| Clustering | K-means, hierarchical, DBSCAN |
| Dimensionality | PCA, t-SNE |

Bias–variance tradeoff: underfit = high bias, overfit = high variance; more data and regularisation push variance down.

## Precision vs recall [RAKUB ANSE-2026]

- **Precision** — of the cases the model *flagged*, how many were real (low precision = false alarms).
- **Recall** — of the *real* cases, how many the model caught (low recall = missed failures).

When a missed event is catastrophic (network hardware failure → outage), optimise **recall**: a false positive costs an inspection, a false negative costs the business. Levers: lower the classification threshold, weight the minority class higher in training, ensemble several models, route anomalies to human review.

<Callout type="info">
Complement pairs to memorise: false positive hurts precision; false negative hurts recall. "Catastrophic miss" questions always want recall.
</Callout>

## Preprocessing: missing values & noise [Combined Bank AP-2023]

**Missing values** — delete sparse rows/cols (only if small & random); mean/median/mode imputation; forward/backward fill (time series); predictive imputation (KNN/regression); constant or "Unknown" label. Example: age column 10% blank → fill with mean age.

**Noise** — binning (bin average/median); regression smoothing; outlier detection via **Z-score or IQR** (a sudden 500°C reading → cap at median); moving-average/Gaussian filters; clustering out the points that belong to no group.

## Neural nets basics

Perceptron → multi-layer network → backpropagation. Activation functions: sigmoid, ReLU (default), softmax for output layers. CNNs for images, RNN/LSTM/Transformers for sequences.

## Big data stack

- **Hadoop** = HDFS (storage) + MapReduce (batch compute) + YARN (resource manager).
- **Spark** = in-memory compute, ~100× faster for iterative jobs; supports SQL (Spark SQL), streaming.
- **Kafka** = real-time stream ingestion; **Flume** = log/clickstream ingestion into HDFS; **Hive** = SQL-like warehouse queries; **Mahout** = scalable ML (clustering, classification, recommenders).
- **V's of big data**: Volume, Velocity, Variety (+ Veracity, Value).

<Callout type="info">
MapReduce ↔ Hadoop is the single most repeated big-data pairing in recent BD IT papers.
</Callout>

### Pick-five Hadoop component drills

The same question shape returns with different scenarios — choose five and justify by role:

| Component | One-line role |
| --- | --- |
| HDFS | distributed, fault-tolerant petabyte storage |
| YARN | cluster resource manager, job scheduling |
| MapReduce | parallel batch processing (map → reduce) |
| Hive | SQL-like querying for analysis/reporting |
| Flume | real-time log ingestion into HDFS |
| Kafka | streaming message bus for live event capture |
| Spark | fast batch **and** stream analytics + ML |
| Mahout | clustering/classification/recommendation engines |

- **Generic pipeline** [Combined Bank AE/AME 2026]: HDFS + YARN + MapReduce + Hive + Flume → ingestion, storage, processing, resources, analytics.
- **Fraud analytics + maintenance prediction** [CB AME/AE 2023]: HDFS + Kafka + Spark + Hive + Mahout.
- **E-commerce recommendations** [CB AME/AE 2023]: Flume + HDFS + YARN + MapReduce + Mahout.

## Bayes drill [ICB AP-2026]

Server X takes 60% of traffic with 2% high-latency risk; Server Y takes 40% with 4% risk.

```text
P(L)  = 0.6×0.02 + 0.4×0.04 = 0.028        (2.8% overall)
P(X|L)= 0.012 / 0.028 = 3/7 ≈ 0.4286        (Bayes)
```

A delayed request is more likely from Server Y. Total probability first, then Bayes — the two-step pattern every conditional-probability MCQ follows.

## Generative AI & XAI [Combined Bank SO(IT) 2025]

A government citizen chatbot: **Generative AI** (LLMs) writes human-like answers, summarises long policy documents, extracts key points from official sources. **Explainable AI** shows *why* an answer was given — the source policy and reasoning — yielding transparency (citizens see the derivation), reliability (officials can audit), accountability (justified responses, less misinformation), and public trust.

<Callout type="tip">
XAI answers are almost always four words: transparency, reliability, accountability, trust. Memorise the quartet.
</Callout>
